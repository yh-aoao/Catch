# Bounce 抓取奖励与手指控制诊断（2026-10-28）

本轮只读审查、调用真实奖励函数验证、运行已有 Catch 模型；未修改业务奖励、物理、控制或模型。结论针对当前本地代码，不证明训练机历史代码完全相同。

## 明确缺陷

1. BounceEnv 手部观测是12维 ndarray，grasping 奖励却访问 obs["hand"]["joints"]，异常静默捕获，使闭合、同步、方向、关节链四项奖励均为0。后续索引也基于16维，不能只修改字典访问。
2. Catch 路径虽计算速度匹配、掌心方向、手指方向，最终两阶段总奖励均未使用这些项。
3. 手部动作是增量角目标；目标累加未按关节范围裁剪。当前模型4局诊断全部出现目标越限，实际关节也出现配置范围外状态。
4. 稳定奖励只依赖策略步内曾有接触和时间，没有要求持续接触、低相对速度及离地。抓取期控制惩罚不含手部。

## 4局动作诊断

模型：bounce_catch_best_reward_288.46.pth；原始球/棒球各 seed0、1。

| 球类/seed | 目标越限步数/总步数 | 最大目标越限（rad） |
|---|---:|---:|
| default / 0 | 29/31 | 3.796 |
| default / 1 | 26/28 | 3.270 |
| ycb:baseball / 0 | 19/21 | 2.391 |
| ycb:baseball / 1 | 20/22 | 2.442 |


原始球seed0中，中间一根手指的三个可控屈曲关节终局目标约[-4.110,-2.190,-1.955] rad，下限[-.314,-.506,-.366] rad。这与反向折弯/持续顶限现象一致；四局是故障复现，不能估计整体发生率。

## 建议顺序

1. 保留当前版本和模型作为对照，修复手部观测/关节语义，限制目标角到模型关节范围，检查执行器力矩与实际限位行为。
2. 用奖励分项日志验证各项实际非零且量级合理，再设计靠近时准备开度、接触后包球、接触时低相对速度、持续离地保持的奖励。
3. 手指约束按每指实际自由度设计，不强制所有手指角度相同，不用无限增大屈曲角作为抓取目标。
4. 新版先训练 Catch 并对照三种球；同时报告接触成功、持续接触、最终离地保持，避免只用距离代替抓握成功。

## 阶段切换更正

当前Bounce生效路径：距离<0.25m进入grasping，随后>=0.25m以ball_left结束。旧0.12m+掌心朝向分支不在当前Bounce生效路径中。

视频有助于确认视觉对应：5–10秒侧面/斜侧面，包括接触前、闭手和丢球，注明球类和命令；不必等待视频才能确认上述代码缺陷。
