# Roll 坐标验证

实际重建当前 Roll/Bounce 环境，打开手指后读取掌部网格至 link6 坐标，PCA 分析厚度轴；将一根手指 MCP/PIP/DIP 正向弯曲 0.3 rad，读取指尖变化。未修改生产奖励、模型或成功条件。

掌部薄轴为 [0.02655,-0.26748,0.96320]，距 +Z 约15.6°，与Y轴夹角约74.5°。网格包含掌部非平面结构，PCA不能独自定义精确接触面法向；手指弯曲朝+Z的运动学证据共同支持+Z是主要握持侧。

指尖变化约 [0.000014,-0.01744,+0.05277] m。Roll 和 Bounce 结果一致。

代码：Roll _roll_capture_point 使用 local +Y；scoop 使用 xmat[2,1] 奖励Y向上；roll_grasp 将Y作深度、X/Z作掌面。Bounce使用+Z。以半径4cm为例，仅将偏移从Y改Z，捕获点相距5.66cm。scoop权重3时，忽略增量项，Y竖直向上获得3分，而Z竖直向上/Y水平获得0.75分。

现有 Catch 接触后会跳过 grasp_terms 的姿态/入口奖励，保留接触质量反馈；故不能声称入口误判解释所有接触后失败。捕获点仍用于跟踪/距离相关计算，scoop仍进入奖励。

结论：确认坐标语义不一致；未证明修正后的策略成功率会提升。建议单独新增奖励版本，校准实际接触面的中心/偏移和掌面边界；不是仅把所有Y字母替换成Z。保持旧模型评估条件，重新训练或小步微调作受控对照。
