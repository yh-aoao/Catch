# Basket Catching 检查记录

日期：2026-09-12。范围：当前 `throw_basket` 的 Catching / Catching_TwoStage。
本轮按用户要求先检查，未修改 basket 奖励、释放机制、失败条件或训练分支。
证据来自代码、执行实际代码分支的 CPU 验证及 XML 静态 FK；没有运行完整 MuJoCo 物理训练。

## 结论

目前存在确定的坐标和终止错误，建议修复后再开始长时间 Catching 训练。
Tracking 停车已经可用，不代表 Catching 的投篮奖励和成功率可信。

## 1. 相对坐标与世界坐标混用（最高优先级）

`DcmmVecEnv._get_relative_object_pos3d()` 返回球相对 arm_base 的位置，XY 还旋转到
车体坐标系；`_get_obs()` 将其放入 `obs['object']['pos3d']`。
Basket 的 `compute_reward()` 分支和 `step()` 入篮分支，却直接将它减去世界坐标
`self.basket_center`。距离、高度、方向、入篮和部分失败判定都受影响。

CPU 执行实际奖励/成功分支的反例（这里只比较分支，不代表完整物理回合）：
设 arm_base 世界位置 `[0,0.32,0.4186]`、yaw=0、框中心 `[0,2.2,0.9]`。

| 真实球的世界位置 | 真实到框心距离 | 代码算出的距离 | 入篮分支 |
|---|---|---|---|
| `[0,2.2,0.9]` | 0 | 约 0.5269m | 失败 |
| `[0,2.52,1.3186]` | 约 0.5269m | 约 0 | 成功 |

应让奖励和几何判定统一使用真实世界位置/速度；策略观测可继续使用相对坐标，不必因此改观测维度。

## 2. 沿用来球的世界 Y 越界规则，会过早结束持球阶段（最高优先级）

`_step_mujoco_simulation()` 通用分支仍把 `obj_y < 1.0 or obj_y > 4.0` 当作失败，
Catching 会采用这一结果。当前 basket 正常持球位置恰好可能小于 1m。

按当前 XML、初始关节与持球公式做静态 FK，初始球世界 Y 约为 0.443m；
底座前移 0.2m 后仍仅约 0.643m。它们都低于通用截止线，因此准备阶段就可能终止。
应给 basket 单独的持球/飞行失败条件，不能使用外部来球的越界规则。

## 3. 加载 Tracking 不等于冻结 Tracking

当前 `ppo_dcmm_catch_two_stage.py` 用 `Adam(self.model.parameters())` 优化全部参数，
`models_catch.py` 的动作概率包含所有动作，Tracking 分支没有 detach 或冻结。
训练时其输入归一化也继续更新。

执行当前模型 forward 和优化步骤后，`actor_mlp_t`、`mu_t`、`sigma_t` 均发生更新；
执行训练归一化后，样本计数从 1 变为 9，均值改变。
因此当前实际上是“加载停车模型后联合继续训练”，可能改变已经学好的停车动作。
以前文档中的“冻结底座”说法已纠正。是否冻结应作为明确的后续设计选择。

## 4. 释放和先停车再抛没有衔接

约 0.3s 前强制把球放在手掌附近，之后不检查站位或手指张开就释放，并叠加
世界速度 `[0,1.5,2]m/s`。释放位置还从随掌姿计算的持球点切到 `link6+[0,.05,-.05]`，
会发生位置跳变。这不能视为已经学会真实持球与自主释放。

圆框横移最大约 0.8m，底座限速 0.8m/s，即使不计加减速也需要约 1s；
0.3s 无法覆盖先到位的需要。应明确停车、准备与释放条件，而不是简单扩大时限。

## 5. 手部奖励存在相互冲突及持续赚分的问题

释放后既奖励张开，又按正向屈曲角总量奖励关节链，闭得更深反而可能得分更高。
例如合法屈曲关节均为 1rad、被锁定的 joint12 保持 0 时，这组手部奖励约 7.35/步，
全张开约 3.6/步，与释放后张开的意图不符。
站位和手部奖励等在释放后持续发放，也可能让回报更多反映回合长度及姿态，而不是入篮能力。
应按持球/出手/飞行阶段启用对应奖励，检查其量级及与主目标的一致性。

## 6. 入篮奖励与成功条件不是同一事件

奖励按三维框心距离 `<0.2m` 给分；成功按到倾斜框平面的距离 `<0.04m` 且平面内
距离 `<0.2m` 判定。二者不等价。成功还没有检查跨越方向、释放状态、完整球体穿框余量，
只在离散策略步检查接近平面，也可能漏掉高速穿越。
圆框 geom 本身关闭碰撞，属于视觉目标，应明确使用几何穿框事件作为统一判据。

## 统计与后续顺序

两阶段训练/测试已经通过 `terminal_metrics()` 使用回合末 `final_info`，未发现之前那种
自动 reset 覆盖成功标志的问题。本轮主要错误在环境判据。
Catching best checkpoint 仍缺少“至少已有完整回合”的保护，也应补上。

建议修复顺序：

1. 统一世界坐标，隔离 basket 专属失败判定。
2. 用同一个穿框事件驱动成功判定和入篮奖励。
3. 衔接停车、准备、释放，并去掉释放位置跳变。
4. 明确底座是否继续训练，同时处理其归一化策略。
5. 清理手部冲突奖励、持续正奖励和空回合 best 统计。
