## 测试证据

用户测试片段包含5个完整回合：停车5/5、合格释放3/5、安全入框1/5，未记录危险机器人碰撞。
两次提前释放发生在最后手接触时底盘速度0.1060、0.1118m/s，略高于0.10m/s门槛；
另两次合格抛出后的预测入口误差为0.2764、0.2087m，最终落地。成功回合误差0.1245m。
这是短片段统计，不能推广为整个训练的成功率。

停车点相对框的Y间距固定约0.934m（arm_base到框中心的Y差，不是手到框的距离）。
X对齐框中心。旧版允许世界X/Y各0.10m误差，二维距离可大于0.10m。
实际停车位置会在容差内变化；不是模型学习选择任意投掷距离。
第一回合2秒时已距离停车点0.0187m，但速度仍0.2207m/s；说明经过停车点时减速不足。
倒退与超调修正一致，不能解释为策略在主动选择最佳投掷距离。
旧版开放臂手后仍允许策略继续驾驶，因此出手时还可能再次超过速度门槛。

## 为什么不直接冻结旧投掷Actor

诊断尝试在手写导航到位后调用旧固定基座Actor，使用原35维归一化和18维动作。
输入中原固定任务停车误差的常量参考[0,0.2]也作了对应处理。
10个种子中0次安全入框：落地3次、机械臂自碰撞5次、提前释放2次。
这证明简单冻结和衔接没有在该诊断中复现旧技能，不能直接作为训练方案交付。
导航期间物理托球后球/手/机械臂状态与原开局出手不同，需要适应。
诊断结果保存在 `analysis_artifacts/basket_transfer_20261027/frozen_probe.json`。

## 可选迁移版本

新配置 `basket_mobile_transfer` 沿用静止随机目标和物理持球任务，仍是51维观测、20维动作。
使用旧固定基座权重作为初始化，之后PPO可以更新整个Actor，包含臂手。

- 旧Actor隐藏层按名称、形状严格加载；首层35列复制到51列前35列，新增16列初始化为0。
- 旧18维输出复制到新输出第2～19行，按臂6＋手12排列；底盘前2行初始化为0，探索标准差单独初始化。
- 复制旧35维输入均值/方差；新增16维使用均值0、方差1。
- 原固定任务停车Y特征的参考值为+0.2，新停车参考为0，故对应归一化均值减0.2，保留参考姿态下的Actor输出。
- 输入归一化统计冻结，避免小批量移动数据重写原尺度；Actor权重仍参与训练。
- 价值网络和回报归一化重新初始化，避免把旧固定任务回报当作移动任务价值。
- 学习率由5e-4降至1e-4。
- 模型保存来源文件名/SHA256、迁移方式、归一化冻结标志与完整移动任务参数；测试检查任务参数一致。

数学等价测试保证参考观测经过上述映射后，臂手Actor均值与旧模型一致。
这不等于实际移动后立即具有相同入框率；实际状态仍有变化，需训练和独立评估。

## 停车控制改动

仅迁移配置默认开启，原 `basket_mobile` 配置仍保持原行为，方便复现旧模型：

- `approach_braking=true`：按剩余停车距离限制速度指令范数，公式上限为
  `min(max_speed, sqrt(2*max_acceleration*max(distance-position_tolerance/2,0)))`。
  方向仍由策略输出，这个限制不自动驶向目标。实际停车仍受动力学影响，不保证完全无超调。
- `brake_after_unlock=true`：停稳开放臂手后保持零底盘速度请求，继续经过加速度限制和原PID控制。
  不修改底盘位置或实际速度，不把底盘重新焊接固定。
- 开放臂手条件收紧为X/Y各0.07m、速度<0.06m/s、持球连续停稳0.30s，减少旧技能出手时的偏差。
- 奖励仍沿用移动版的导航、停车、飞行距离、瞄准、命中和安全惩罚，不按旧固定奖励继续训练。

## 训练

```bash
conda activate dcmm
cd /home/isee/Catch/catch_it_copy
python3 train_DCMM.py --config-name basket_mobile_transfer \
  test=False num_envs=32 vector_mode=async device_id=0 \
  basket_warm_start=/home/isee/Catch/10-25/throw_basket_catch_best_reward_39.44.pth \
  viewer=false basket_log=false basket_self_collision_debug=false \
  output_name=BasketMobileTransfer
```

`basket_warm_start`是迁移初始化；不要把旧权重传给`checkpoint_catching`。
该配置从新的优化器/价值网络开始，Actor利用旧投掷模型，底盘输出重新初始化。
原从零训练配置仍可使用。建议保存当前移动模型作为对照，不以文件名best_reward判断入框效果。
