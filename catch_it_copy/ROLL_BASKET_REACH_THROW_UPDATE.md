# Roll 站位与 Basket 物理投掷塑形更新

本轮针对用户反馈的 Roll 先后退、未靠近拦截区域，以及 Basket 臂不动而手仅轻微动作。
代码已修改；尚未验证训练后的实际效果。

## Roll

- 进展项改为 `5*(||当前目标-上一末端位置||-||当前目标-当前末端位置||)`。
  两项使用同一个当前目标，因此落点自行漂移不会让静止机器人获得进展奖励。
- 加入底座距离区间：预测落点与 arm_base 的水平距离以 0.35–0.65m 为初始参考。
  超出区间按距离扣分，权重 2；区间内平移速度平方惩罚权重 0.1。
  这是可调的水平距离启发式，不是完整 IK 可达性证明，不保证无自碰撞。
- 球仍在桌上时，到达拦截点并停稳获得最多 0.5/步的 arrival 奖励。
- 保留原高度、手桌余量、控制和碰撞项；未硬性禁止后退，未修改动作或观测维度。

## Basket

保留物理投掷：停车后不再写球速度/位置，不恢复定时释放或额外弹射速度。
停车策略及默认冻结行为不变。新塑形补充在现有分阶段奖励之上：

- 根据当前球位和框中心枚举 0.25–1.5 秒飞行时间，求解能到达框心的初速度；
  只保留穿框时沿框法向下降且速度不超过 6m/s 的候选。
- 速度质量为 `exp(-最小速度误差平方/1.5²)`。接触期间奖励质量改善，权重 5；
  比较时使用同一球位、同一框位置，只改变前后球速，避免站位改变冒充加速进展。
  质量下降会扣分，静止保持高质量不会持续刷取这一项。
- 真实接触且球速 <0.3m/s 时给予初始支撑奖励，总计最多 0.2 分/回合。
  支撑姿态没有另加硬编码闭合奖励，避免手只顾弯曲；物理抓持仍需仿真验证。
- 自然脱手时质量至少 0.4 才有一次性 `5*质量` 奖励，最多 5 分。
  同一步明确失败时不给该奖励；后续掉球仍按既有失败条件扣分。
- 原实际弹道误差、飞行进展、控制、时间、失败和真实穿框奖励继续保留。

`basket_log=true` 的 `[basket-catch]` 增加 `control`：
`arm_action_norm`、`ik_attempts`、`ik_successes`、`arm_joint_speed`、
`hand_contact`、`ball_velocity`、`reference_velocity`、`quality`、`release_quality`。
动作范数是缩放后的臂动作，关节速度范数单位为 rad/s；IK 计数为本回合累计。

若 phase 一直 parking，机械臂本来就被固定；若 preparing 后 IK 次数增长但成功率低，
优先检查动作/IK；若 IK 成功但实际关节速度低，检查执行器与 PID；若没有有效手球接触，
优先检查持球初态。奖励改变不会修复这些物理或控制故障。

## 使用

同步主环境、`roll_rewards.py`、`basket_catching.py`、`DcmmCfg.py` 到 Linux。
建议用新输出目录重训 Roll Track，成功后再训 Roll Catch。Basket 可复用已有合格的停车
checkpoint，重训 Catching_TwoStage。测试分别加 `roll_log=true` / `basket_log=true`。

CPU 测试覆盖目标漂移、站位和停稳倾向、弹道参考速度、支撑奖励上限、一次性出手，
以及既有回归。本机 MuJoCo DLL 无法加载，未进行完整物理仿真和长训练。
因此距离区间和奖励权重是待验证的起始配置，不能据此声称已解决训练效果问题。
