新的两阶段：准备+移动 -> 从真实准备状态抛球

旧 basket_mobile_bridge 及其权重完整保留，未改动。备份源码：
backups/before_prepare_throw_20261126/bridge_source.tar.gz

新包入口 python -m basket_prepare_throw.run，观测66维、动作20维（底盘2、机械臂关节速度6、手指增量12）。
本版本观测使用实测相对手掌速度，独立schema basket_prepare_throw_v1；不能当作旧模型直接续训。
没有物体力辅助、自动刹车、脚本持球姿态或手指锁定。

第一阶段 configs/stage1_prepare.json：从零学习，随机物理支撑持球后，边调整边移动到准备区域。
初始姿态：20条真实Throw/Roll/Bounce接触/持球模板加1条通用杯状模板，再扰动、重力落稳并筛选。
模板数有限，不能解释为覆盖所有接球状态；重置速度为零，尚不是在线接球状态。
准备条件：
- 底座到篮筐水平距离.85~1.15m，底座坐标参考矩形x±.10、y.85~1.15m附近（距离<=.05m）；
- 球在手掌局部x[-.045,.045]、y[-.015,.095]、z[.045,.12]m，且仍接触支撑；
- 手掌局部z轴的竖直分量>=.25，手臂各受限关节归一化限位余量>=1%；
- 相对滑速<.12m/s，手臂关节速度范数<1rad/s，底盘速度<.05m/s、连续低速>=.12秒；
- 上述条件连续维持.3秒且无危险碰撞。
这是宽松几何/稳定性先验，不保证一定最适合抛球，最终由第二阶段投篮结果验证。
准备成功+40，失败-20；保留持球和导航奖励，另有弱姿态质量及一次性最佳质量进步奖励。
移除准备阶段的弹道、释放、释放距离和进筐奖励；不指定精确手型。
课程preparation_level0/1/2的篮筐y范围分别1.35~1.5、1.6~1.9、1.8~2.4m。
前两级独立评估连续两次>=80%才升级；teacher_best优先选择最高已评估等级，再比较成功率。
建议最终level2的评估成功率稳定>=80%后再进入第二阶段，不要使用早期level0/1权重。

收集准备状态：python -m basket_prepare_throw.collect_ready，是推理，不是额外RL阶段。
先把第一阶段teacher_best复制为固定文件，收集500条成功状态；同一个固定文件用于第二阶段初始化。
完整保存MuJoCo积分状态（含速度、控制输入和warm-start）、篮筐位置、PID历史、关节目标、
动作延迟缓冲、底盘加速度限制历史和上一动作。不会重摆球、恢复预设手型或清零速度。
物理指纹校验防止把状态恢复到不同物理模型。测试在相同执行噪声下重放下一动作结果一致。
银行是reset-only的真实到达状态回放，不是在运行中传送球。

第二阶段 configs/stage2_throw.json：导入新第一阶段权重，所有参数可训练。
60%从准备状态库开始抛球；25%完整准备/移动->抛球；15%第一阶段任务回放。
短抛回合底盘仍然开放；完整回合需达到同一准备条件才切换抛球头，切换不重置物理或控制状态。
完整回合实时到达的成功准备状态还会加入该worker的短抛回放队列（最多1000条）。
保留原进筐、弹道、释放和v2距离奖惩。超出区间距离按线性惩罚结算。
训练prepare_sr、short_throw_sr、full_sr分别报告，不把混合success_100当投篮成功率。
bridge_reached_sr表示完整回合到达抛球阶段的比例。
第二阶段独立eval_success_rate始终测试完整流程，不使用短抛状态库，因此viewer无需携带状态库。
第一阶段成功率不能直接等同投篮成功率，阶段二才是完整效果。

续训本包用--resume。阶段二必须--initialize-from新第一阶段，并--ready-bank指定匹配同一权重的状态库。
状态库采集后请勿覆盖初始化权重文件，否则源文件哈希不匹配会拒绝训练。
服务器上同步新包、以及现有basket_autonomous/gym_dcmm依赖；无需覆盖旧桥接包和权重。
