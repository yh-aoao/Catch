# throw_force 初始夹球姿态设计

## 目标

将 `catch_it_copy` 的 `throw_force` 初始状态从当前的捧球姿态改为扔球准备姿态：灵巧手手背朝上、掌心朝下、手指朝下并夹住小球，随后由机械臂和底盘向前运动完成释放。

## 当前问题与根因假设

`throw_force` reset 时使用 `throw_force_arm_joints`，并在持球阶段把小球放在 `link6` 的 Y 轴方向。代码将 `link6` Y 轴定义为掌心法线，但现有 IK 辅助脚本仍以掌心朝上为目标，导致配置中的姿态语义与 IK 计算不一致。初始手指虽然弯曲，但球的位置主要由掌心法线偏移决定，不能保证落在手指夹持区域。

## 设计

### 机械臂姿态

修正 `compute_throw_force_ik.py` 的目标旋转：

- `link6` Y 轴（掌心法线）指向世界负 Z，表示掌心朝下。
- `link6` Z 轴（手指方向）指向世界负 Z 与正 Y 的组合方向，表示手指朝前下方。
- 通过 MuJoCo IK 求解可达关节角，并将结果写入 `DcmmCfg.throw_force_arm_joints`。

### 灵巧手与球的位置

保留 `throw_force` 专用的预弯曲手指配置，并根据实际关节限位检查三指与拇指的闭合程度。reset 和持球阶段统一使用掌心法线计算球心，使球位于掌心下方、靠近手指夹持区；不改变释放阶段的前向速度逻辑。

### 验证

增加或复用一个轻量验证入口，在 reset 后执行 FK 并检查：

- 掌心法线的世界 Z 分量为负；
- 手指方向的世界 Z 分量为负；
- 球心位于掌心法线方向，距离等于球半径加间隙；
- throw_force 的持球阶段没有提前释放，释放后球获得预期的前向速度。

验证优先使用 `compute_throw_force_ik.py` 的 IK 输出和 MuJoCo 环境的单回合 reset；若当前 Windows 环境缺少 MuJoCo/OpenGL 运行依赖，则至少完成无 viewer 的 IK/FK 检查并记录阻塞原因。

## 范围与兼容性

- 只修改 `catch_it_copy`，不触碰 `catch_it`、`catch_it_sac` 和 `old` 备份。
- 不改变 `throw`、`roll`、`bounce`、`throw_basket` 的姿态和行为。
- 不新增训练奖励，不调整释放速度参数，避免把姿态问题与策略学习问题混在一起。

## 风险与回退

IK 目标可能接近 XArm6 关节限位。若严格的掌心朝下目标不可达，保留掌心朝下不变，仅降低手指前倾角，选择 IK 成功且方向指标满足的最近姿态。若球与手指发生初始碰撞导致不稳定，先增大掌心与球的间隙，再单独调整手指弯曲量。
