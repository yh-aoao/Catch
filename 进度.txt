8.2：四任务统一修改

1. UR5e L 型连接件：
   问题：建模修改后训练 catch 效果差，球跟踪到连接件而非手
   结论：运动学变了，旧 track 模型不适用，需重新训练 track→catch
   改动：无代码改动，重新训练即可

2. Roll 固定底座：
   问题：roll_fix_base=True 锁底盘但车在原点，臂够不到 2m 外的台面
   修复：reset 时底盘瞬移到台面前方 1.2m（x 略随机 ±0.3m）
   代码：DcmmVecEnv._reset_simulation() roll 段

3. Bounce 抓取修复：
   a) 阶段切换：
      问题：0.25m（跟 throw）太松 / 3cm（原始）太紧
      修复：独立切换逻辑——d_3d < 0.10m 且掌心朝球(palm_dot>0.7)，不要求 no_contact
      效果：grasping ~10-15 步，足够闭合手指
   b) 预闭合奖励：
      问题：tracking 阶段无手指闭合引导，摸着石头过河
      修复：reward_pre_close = 2.0 * proximity * mcp_flex
            proximity = exp(-d_3d/0.2)，距离越近手指越该闭合
      代码：DcmmVecEnv.compute_reward() Catching tracking 段

4. Throw_Basket 手指参与：
   问题：手指固定杯状，不参与抛球，无法学会"手臂甩+手指张"协调
   修复：
   a) 初始握球姿态改为 grip（MCP=1.5, DIP=1.0, 拇指=0.8）= 像人握球
   b) _step_mujoco_simulation 不再覆盖 target_hand_qpos，模型自由控手
   c) 保持 0.3s 持球+释放机制，模型学会在释放时张开手指
   d) 不需要两阶段训练，单阶段 Tracking 即可

5. throw_basket bug 修复：
   - 观测空间 basket 字段改条件添加，仅 throw_basket 模式
   - obs2tensor 改为按内容自动拼接（不再按 task 分支）
   - ball_in_hand 接触不触发 early_term

6. roll 微调：
   - 去掉底盘瞬移，改为球移近(y=0.9~1.4)+速度降低(0.3~0.6)
   - 小车前移 qpos[1]=0.4
   - 台面降低 roll_table_height=0.55

8.25：Bounce 奖励函数与手部摩擦总结

一、当前 Bounce 奖励函数

Bounce 的奖励在 `gym_dcmm/envs/DcmmVecEnv.py` 中单独实现，不再直接使用 throw 的位置奖励。主要由以下部分组成：

1. 3D 位置奖励：根据机械臂末端与小球的三维距离计算稠密奖励，距离越近奖励越高，参数为 `bounce_w_3d=1.0`、`bounce_sigma_3d=0.45`。
2. 3D 靠近奖励：比较前后时刻末端与小球的距离，只有距离缩小时给奖励，参数为 `bounce_w_approach=5.0`。
3. 速度匹配奖励：根据末端速度与小球速度的差异给奖励，鼓励机械臂跟上弹跳小球的运动，参数为 `bounce_w_vel_match=2.0`、`bounce_sigma_vel=0.3`。
4. 掌心朝向奖励：使用 link6 的 Y 轴作为掌心法线，鼓励掌心朝向小球，而不是固定朝向某个方向。使用平方非线性、方向改善增量和小角度 bonus，主要参数为 `bounce_w_palm_face=8.0`、`bounce_w_palm_face_bonus=3.0`。
5. 手指方向奖励：鼓励手指方向指向小球的 XY 方向，同样包含平方非线性、方向改善增量和 bonus，主要参数为 `bounce_w_finger_dir=8.0`、`bounce_w_finger_dir_bonus=3.0`。
6. 掌心与手指协同奖励：当掌心方向和手指方向同时改善时增加奖励，参数为 `bounce_w_coordinated=2.0`。
7. 跟踪阶段手指姿态奖励：鼓励多指 MCP 同步、单指关节链同向弯曲，并惩罚同一手指关节方向混乱。
8. 抓取阶段手指闭合奖励：根据 MCP 平均屈曲程度奖励手指闭合，并根据 MCP/PIP/DIP 是否同向弯曲增加或扣除关节链奖励。
9. 通用奖励：仍保留控制惩罚、底盘碰撞惩罚、关节限位惩罚、接触奖励；进入抓取阶段后还保留物体稳定时间奖励。

二、Bounce 与原 Throw 奖励的区别

1. Throw 的核心位置奖励是底盘/末端距离的逐步减少，以及末端精度奖励；Bounce 改为三维距离即时奖励加三维靠近增量，更适合小球上下弹跳的空间轨迹。
2. Throw 的姿态奖励主要使用小球速度方向与末端姿态的关系；Bounce 额外强调掌心法线朝向小球和手指朝向小球，形成面向碰撞的接球姿态。
3. Bounce 新增末端速度与小球速度匹配奖励，Throw 没有这一项。其目的是减少接触时的相对速度，降低小球碰到手掌后弹飞的概率。
4. Bounce 在跟踪阶段加入手指同步、手指关节链和预闭合相关设计；Throw 原始任务不需要针对弹性碰撞提前准备手指。
5. Bounce 在抓取阶段加入手指闭合及关节链奖励，并且成功判定要求掌心接触、球速连续降低、距离足够近、手指达到闭合阈值且球离地；Throw 的原始成功逻辑没有这些针对弹性小球的严格条件。
6. Bounce 的物理环境还会随机化弹性系数、接触阻尼、地面摩擦和球体阻尼，因此其目标从 Throw 的自由飞行跟踪，变成弹跳轨迹跟踪与碰撞后的稳定抓取。

三、Bounce 是否启用了手掌摩擦

已经启用。每次 Bounce reset 时，代码会遍历灵巧手的 16 个碰撞几何体，并将其摩擦系数动态设置为：

`bounce_hand_friction = [2.0, 0.5, 0.1]`

对应 MuJoCo 的滑动摩擦、扭转摩擦和滚动摩擦。相比默认值 `[1.0, 0.005, 0.0001]`，滑动、扭转和滚动摩擦都明显增大，作用是让小球接触手掌后消耗更多动能、减少立即弹飞，因此确实会使小球更容易减速并停留在手部附近。

但小球是否快速停下不只由手部摩擦决定，还同时受到小球与地面的摩擦、球地响。因此当接触阻尼、弹性系数、自由关节阻尼以及碰撞姿态的影前实现更准确的表述是“手部高摩擦有助于吸收接触后的切向运动并降低弹飞概率”，不能单独断言小球停下完全由手掌摩擦造成。
————当前滑动摩擦属于较高水平，需要给摩擦做泛化、消融
